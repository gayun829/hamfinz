# 상점 상품과 구매 규칙

## 카테고리와 가격

화면 탭은 `my / 세트 / 스킨 / 옷 / 악세서리` 순서다. my는 보유 상품만 표시하고,
옷장은 모든 탭에서 보유 상품만 표시한다. 상점은 미보유 상품을 먼저 표시한다.
기본 스킨은 무료, 일반 스킨은 600씨앗, 옷은 150씨앗, 악세서리는 100씨앗이다.
에너지 +20은 60씨앗, 방어권은 300씨앗(최대 4개)이다.
이메일·소셜 신규 프로필 생성 시 방어권 1개로 시작하며 기존 계정에 추가 지급하지 않는다.

## 세트

- 닌자: 닌자 옷 + 닌자 머리 장식 (200씨앗)
- 유치원생: 유치원복 + 머리카락 포함 모자 (200씨앗)
- 지니: 지니 옷 + 머리와 수염 (200씨앗)
- 넥타이: 회색 몸 스킨 + 넥타이 (560씨앗)

가격은 미보유 구성품 정가 합계 × 80%, 소수점 올림이다.
닌자 옷을 보유하면 세트는 80씨앗, 머리 장식을 보유하면 120씨앗이다.
전부 보유하면 재결제 없이 착용한다. 구매 트랜잭션은 최신 소유 목록에서 가격을
다시 계산하고 세트 ID와 구성품 ID를 함께 저장한다.
기존 완성형 세트 ID 구매도 구성품 보유로 인정한다.
이전 유치원·지니 장식 세트 구매 내역도 개별 구성품으로 인식한다.
파마 머리와 빨간 안경은 하나의 악세서리(100씨앗)로 묶는다.

## 착용

스킨·옷·악세서리는 각각 1개만 착용한다. 같은 카테고리 선택은 기존 항목을 교체한다.
세트 선택은 포함된 카테고리들을 함께 교체하고 다른 카테고리는 유지한다.
옷 ID는 기존 `equippedPatternId` 필드를 재사용하며 악세서리는
`equippedAccessoryIds`에 최대 1개를 저장한다. 기존 필드 이름은 호환성을 위해 유지한다.
기존 완성형 세트는 옷장에서 개별 슬롯으로 풀어서 편집하고 저장한다.
분리 파일을 아직 받지 못한 안대·군필 등 완성형 중복 상품은 신규 판매 목록에서 숨기되
구매 이력은 지우지 않고 my에서 확인할 수 있다. 빨간 옷은 파일 수령 후 추가한다.

## 카탈로그와 배포

Dart는 `lib/data/shop_data.dart`, Functions는 `functions/shop_catalog.json`을 사용한다.
`functions/shop_catalog.test.js`가 양쪽 상품 ID·가격·세트 구성 일치를 검증한다.
번들 상품은 코드 가격이 우선이며 Firestore로 번들 가격·활성 상태를 변경할 수 없다.
현재 구매는 개발용 Firestore 클라이언트 트랜잭션이며 Functions 구매로 전환할 때
`functions/index.js`와 카탈로그 모듈도 함께 배포한다.

상품 목록과 이미지는 로컬 코드와 asset만 사용한다. 앱과 Functions 구매 처리에서
Firestore shopItems 조회·원격 가격·원격 이미지 지원을 제거했다.
등록되지 않은 상품 ID는 구매할 수 없다. 새 상품/가격 변경은 앱 업데이트와
Functions 배포가 필요하다. 유저의 씨앗·보유·착용 데이터는 Firebase에 유지한다.
firestore.rules와 firestore.rules.production의 shopItems 클라이언트 접근은 차단한다.
실제 DB의 테스트 상품 문서 삭제와 규칙 배포는 아직 실행하지 않았다.
몸과 부품은 동일한 384×384 좌표계의 asset으로 관리한다.

## 검증과 화면 캡처

`flutter test test/shop_bundle_test.dart test/shop_failure_test.dart`는 할인·착용·실패 흐름을 검증한다.
화면 PNG 생성은 명시적으로 `flutter test --dart-define=SHOP_PREVIEW=true test/shop_design_preview_test.dart`를
실행할 때만 동작한다. 일반 CI 테스트에서는 폰트 로드나 PNG 저장을 하지 않는다.
